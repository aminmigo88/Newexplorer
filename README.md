# Newexplorer 0.5.1

An iPhone file explorer for copying files between two independently navigable panes. The panes stack in portrait and sit side by side in landscape.

## Try the first build

Open Newexplorer.xcodeproj in Xcode, select the Newexplorer scheme and an iPhone running iOS 17 or later, and run the app. The project resolves AMSMB2, LibArchive and ZIPFoundation with Swift Package Manager.

1. On first launch, both panes show **App files**, Newexplorer’s own Documents folder. In pane A use **Browse Files locations** to navigate iCloud Drive, On My iPhone or another available provider and select files to preview or copy. Use **Open a folder in this pane** to browse a whole directory, then confirm the current directory with the picker’s Open or Done button. Each provider controls which folders it can return. On the tested simulator, the On My iPhone root returned a folder that omitted other apps’ shared folders. Browse Files locations shows the system listing and lets you choose individual files there. Choose **Open Photos** for the photo library. In pane B tap **Connect to Windows** for a Windows destination. These choices are also in each pane’s location menu. Enter the computer name or IP address, the shared folder name and the credentials for a Windows account with access to that share. Both devices must be able to reach each other on the LAN. Credentials live only in memory.
2. Choose **On My iPhone** or **iCloud Drive** from a pane's location menu. The first time, press Open at the top level of that location in Files. iOS gives an app only the items stored directly at that top level; each app's folder (and in iCloud Drive each app's folder such as Pages) is a separate grant, so use **Add app folders** and tick the ones you want, several at a time if the picker allows. Both panes share the list and reopen it after a relaunch. Long-press an added folder to rename it in the list or remove it. Paste and New folder act on the top level. iCloud files that are not downloaded show a cloud icon and download when you open or copy them.
3. Tap a file, photo or video to open it in Newexplorer’s viewer. Swipe left or right for the next or previous file in the list, in the order shown. **ⓘ** shows the name, kind, size, dates and folder, plus camera data (dimensions, camera, lens, aperture, shutter speed, ISO, date taken, GPS coordinates) for photos and duration, resolution and frame rate for videos. **Send to A** or **Send to B** copies it into the other pane in one tap, the same as Copy and Paste here. Send is hidden when the other pane shows Photos, iCloud Drive, Selected files or the folder the file is already in.
4. Tap the ✓ button at the top of a pane to show the circles, tick files or folders, then **Copy**. Tap ✓ again to hide the circles and clear the ticks. In the other pane tap **Paste here**. Each item is staged before it gets its final name. A filename conflict stops the batch and leaves the remaining items on the shelf. The phone needs temporary space for one selected item at a time. Keep the app open for large transfers.
5. In Photos, allow selected or full access. Photos opens to folders: **All**, **Pictures** (camera shots: photos with a location, Live, HDR, Portrait, Panorama or burst photos, or the camera’s HEIC or RAW format), **Videos**, **Screenshots** and **Others** (every other image, such as saved or downloaded ones), then one folder per album with its name from Photos. iOS doesn’t let apps read which app saved an image, so Pictures and Others are a best guess. **Show more photos** adds the next 150 below and keeps your place. Pasting into an album folder also adds the item to that album. Copy and Send give one file as Photos shows it: the edited version when there is one, and only the still image of a Live Photo. iCloud may need to download an original. Pasting a single supported image or movie into Photos imports it.
6. Tap a ZIP, RAR, TAR, TGZ or ISO file to browse it like a folder without extracting it. Files inside open in the viewer, and Copy then Paste unpacks only the selected items. Archives are read-only; 7z, password-protected archives, archives on a Windows share and archives inside archives aren’t browsed. In a Files folder, long-press an item for **Create ZIP**, choose **Extract here** on a ZIP or RAR file, or use the pane menu to find exact duplicate files and empty folders. Use Search to filter the loaded location. The pane menu also provides New folder, selection controls and **Sort by** Name, Date, Size or Kind. Choosing the current order again reverses it. Folders stay on top, each pane remembers its order, and the Photos list keeps its own order (newest first by default, no Size). Long-press to rename or delete an item. Delete selected removes the selected files after confirmation. The report groups nonempty files by size and SHA-256. A scan can download cloud-backed files. File contents alone do not indicate whether deleting a copy is safe. Use the review to choose which copies to delete through the file browser. The app menu can clear temporary transfer files.

## Signing

The bundle identifier is `app.ximenia9398.cheetah4988`, the App ID in the signing profile. iOS hands Files folders only to an app whose bundle identifier matches the App ID it is signed with, so a different signing profile needs `PRODUCT_BUNDLE_IDENTIFIER` changed in Scripts/generate_project.py.

## Current scope

This first version uses the app’s documents folder, directories granted through the iOS picker, PhotoKit and authenticated SMB shares. Each pane remembers its most recently opened Files folder and can reopen it from its location menu. A pane left in that folder reopens its bookmarked root on launch. Individual file selections last for the session. Network copies may leave a temporary .NX- item on a share if the Wi-Fi connection is lost. The scanner is read-only. File deletion is permanent outside Photos, so confirm the selected location and items. Photos deletion also affects iCloud Photos and other synced devices. Encrypted or multipart RAR support, archive browsing, destructive moves and reviewed deletion are future work. Native RAR creation requires a separate encoder.

## Validation

The simulator workflow builds the app and runs the local copy, collision, archive and duplicate-scan tests. UI tests check the empty panes, Windows connection form, Photos permission request and recovery after denial, opening a photo in the viewer, sending it to the other pane and the selection switch. First device checks are folder-picker access, limited Photos access, Live Photo still export, and copying in both directions against a real Windows share. For the network check, compare the transferred file with its source and repeat a copy with Wi-Fi disconnected partway through. The source should remain intact. After successful simulator tests, the main-branch workflow builds an unsigned arm64 iPhone app, verifies its embedded framework and packages an IPA for signing with KravaSigner. The signing service must sign the embedded AMSMB2 framework as well as the app.
